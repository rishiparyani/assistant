# Scorecard 2026-10-15: OpenAI's GPT-6 Luna and GPT-6.1 Sol

The owner's question after the small-model comparison: "Why didn't we include these models in our tests?" (ChatGPT had listed GPT-6 Luna, GPT-6.1 Sol and GPT-6 Astra with their prices). Both were added as scorecard candidates (`gpt-6-luna` at the everyday level, `gpt-6.1-sol` at the setups level, `AI_PIN_MODEL=1` so a candidate's misses are its own) and run against the live picks, Claude Haiku 5.5 and Claude Sonnet 5.5, three runs of every case.

## GPT-6 Luna, everyday level (run 38802232233, `suite=all`, `repeat=3`)

| Everyday model       | Core      | Hard       | Hinglish  | Median | Slowest | Cost a message¹ | Thinking |
| -------------------- | --------- | ---------- | --------- | ------ | ------- | --------------- | -------- |
| **Claude Haiku 5.5** | **57/60** | **98/102** | **33/33** | 3.4 s  | 9.3 s   | ≈ ₹0.18         | low      |
| GPT-6 Luna           | 58/60     | 103/105²   | 33/33     | 4.7 s  | 11.9 s  | ≈ ₹0.57         | low      |

¹ From the runs' own token counts at the makers' list prices and cache rates (Luna: $0.10 a million in, $0.50 out, 87% of input from the cache; ₹31.09 a run of the 55 cases). An earlier note to the owner said "≈ ₹0.19": that divided the run's cost by all three repeats; ₹0.57 a message is the right reading, to check against OpenAI's usage page before trusting it.
² The hard suite has grown to 35 cases since the comparison (105 = 35 × 3); Haiku's 98/102 is from the 34-case suite.

**Right every time:** 52 of 55 cases. Every Hinglish case, every date and time case (including "parso subah", which GPT-5.4 mini and nano missed every time), every money case, every "waits for a tap" case, and both handover cases (the only model so far to get `handover-card`).

**What it got wrong (one slip each, three runs):**

- `note` (1/3): shortened the note's title twice ("PA at Test Café" instead of the whole line).
- `ambiguous-tick` (2/3): once ticked "Call Rahul about the gig" instead of asking which of the two matching reminders.
- `delete-all-waits` (2/3): once said "the change card is ready, tap Confirm" without having made the card.

**Reading it:** equal to Haiku on right answers (Luna is one case better on core, the same on Hinglish and dates), about a second slower a case (4.7 s against 3.4 s), and about three times the cost a message by these counts. Haiku stays the everyday pick (decision 2026-10-15 "Haiku for every day, Sonnet for setups"); Luna is the first other maker's model that would do the job as well, which matters as a fallback if Anthropic's API were down or its price moved.

## GPT-6.1 Sol, setups level: could not run

Three tries, `setup_model=gpt-6.1-sol suite=setups repeat=3` (runs 38802234899, 38809785945, 38815122864), each 0/24 with the same refusal on every call:

```
GPT-6.1 Sol answered 400 (unsupported_value, invalid_request_error, reasoning_effort)
```

With `reasoning_effort: "low"`, with `"none"`, and with no `reasoning_effort` at all (the `effort: "model"` entry sends nothing). The 400 names `reasoning_effort` every time, so on `/v1/chat/completions` the model seems to want a value we didn't try or the Responses API altogether (the same limit noted for GPT-5.4 with tools, comparison doc, note ³). The setups fell back to "The smart model isn't available right now", which is the right behaviour for the app and the wrong one for a scorecard. Stopped here: no more tries until the client speaks the Responses API, which is its own task (and is also what would let the GPT models think with tools on).

For scale, the live setups model the same day: **Claude Sonnet 5.5, 24/24**, median 5.5 s, ₹24.28 a run of 8 setups, about ₹3 a setup (run 38802232233, level 2).

## What changes
